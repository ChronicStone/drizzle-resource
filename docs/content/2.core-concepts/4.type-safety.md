description: Field-path unions, typed request context, and inferred row types — what the compiler catches before a query ever reaches the database.

The field paths a resource accepts are inferred from your Drizzle schema and declared relations. A typo in a sort key or a filter path is a compile error, not a 500 at runtime.

## Typed scope filters

Inside `scope`, the filter builder only accepts paths this resource registered, and `ctx` carries the type you gave `withContext`:

```ts twoslash
// @errors: 2345
import { engine } from "./engine";
// ---cut-before---
engine.defineResource("orders", {
  relations: { customer: true },
  query: {
    scope: (f, ctx) => f.is("customer.", ctx.orgId),
    //                             ^|
  },
});
```

Both arguments are checked — the path against the registry, the value against that column's type. The completion list above is the field registry itself.

## Invalid paths fail to compile

```ts twoslash
// @errors: 2345
import { f } from "./twoslash-support";
// ---cut-before---
f.is("customer.orgg", "acme");
```

Discovering what a resource exposes is autocomplete rather than documentation.

## Typed request context

`withContext` fixes the shape of the second `scope` argument and of `query({ context })`:

```ts twoslash [engine.ts]
import { createQueryEngine } from "drizzle-resource";

import { db } from "./db";
import { relations } from "./relations";
import { schema } from "./schema";
// ---cut-before---
export const engine = createQueryEngine({ db, schema, relations }).withContext<{
  isAdmin?: boolean;
  orgId: string;
  userId?: string;
}>();
```

Omitting a required context key at the call site is an error:

```ts twoslash
// @errors: 2739 2741
import { ordersResource } from "./twoslash-support";
// ---cut-before---
await ordersResource.query({
  context: {},
  request: {
    pagination: { mode: "offset", pageIndex: 1, pageSize: 25 },
    sorting: [],
    search: { value: "", fields: [] },
    filters: [],
  },
});
```

## Inferred row types

Rows are typed from the schema and the declared relation tree, including nesting:

```ts twoslash
import { ordersResource } from "./twoslash-support";

const result = await ordersResource.query({
  context: { orgId: "acme" },
  request: {
    pagination: { mode: "offset", pageIndex: 1, pageSize: 25 },
    sorting: [],
    search: { value: "", fields: [] },
    filters: [],
  },
});
// ---cut-before---
const sku = result.rows[0]?.orderLines[0]?.product.sku;
//    ^?
```

## Reusing the path union

Derive the union with `QueryFieldPath` rather than hand-writing it. A hand-written list drifts from the schema and starts certifying paths that do not exist:

```ts twoslash
import type { QueryFieldPath } from "drizzle-resource";

import { ordersRelations } from "./orders.resource";
import type { relations } from "./relations";
import type { schema } from "./schema";
// ---cut-before---
type OrderFieldPath = QueryFieldPath<
  typeof schema,
  typeof relations,
  "orders",
  typeof ordersRelations
>;

// Use it to type your own helpers
function buildColumnFilter(key: OrderFieldPath, value: string) {
  return { type: "condition", key, operator: "is", value } as const;
}
```

Share that type with the client and a front-end column definition cannot name a column the server will reject.

## What types do not check

Static types cover paths, context, and row shapes. They do not cover policy, because policy is runtime configuration:

- `search.allowed`, `facets.allowed`, `sort.disabled`, `filters.hidden` are enforced at query time and throw.
- Operator **values** are typed as `unknown` on the wire, so a `between` given an array compiles and then matches nothing.
- Pagination mode availability is a runtime check against `pagination.modes`.

Validate the wire payload at the boundary to turn those runtime failures into `400` responses — see [Validation](/integration/validation).
