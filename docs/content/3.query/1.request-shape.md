title: Request shape

A call has two parts. `context` comes from your server: the tenant, the user, their permissions. `request` comes from the client and says which page, in which order, with which filters and search.

```ts twoslash
// ---cut-start---
const T = {} as const;
const QueryRequest = {} as import("drizzle-resource").QueryRequest;
declare function resourceQuery(input: {
  context: unknown;
  request: import("drizzle-resource").QueryRequest;
}): void;
const resource = { query: resourceQuery };
// ---cut-end---
resource.query({
  context: T, // set by your server
  request: QueryRequest, // sent by the client
});
```

`context` is never read from the request body. The generated [request schemas](/validation/schemas#request-schemas) reject a body that contains it.

## The type

```ts twoslash
import type { QueryFacetRequest, QueryFilterNode, QueryPagination } from "drizzle-resource";

type QueryRequest = {
  pagination: QueryPagination;
  sorting: Array<{
    key: string; // a field path of the resource
    dir: "asc" | "desc";
  }>;
  filters: QueryFilterNode[]; // combined with AND
  search: {
    value: string;
    fields: string[]; // [] searches the resource's default fields
  };
  facets?: QueryFacetRequest[];
};
```

| Field        | Left empty or out                                 | Details                         |
| ------------ | ------------------------------------------------- | ------------------------------- |
| `pagination` | The resource's default mode and page size.        | [Pagination](/query/pagination) |
| `sorting`    | `sort.defaults`; without defaults, no `ORDER BY`. | [Sorting](/query/sorting)       |
| `filters`    | No filter beyond the scope.                       | [Filters](/query/filters)       |
| `search`     | No search when `value` is empty or only spaces.   | [Search](/query/search)         |
| `facets`     | No facet queries run.                             | [Facets](/query/facets)         |

## Try it

Every field can be edited. Change a key to one the resource doesn't allow, such as `"sorting": [{ "key": "orderLines.product.name", "dir": "asc" }]`, and the engine rejects the request before running any SQL.

::

## What happens before any SQL runs

1. The resource's scope is added to the top-level filters with `AND`.
2. Defaults fill in empty sorting, search fields and page size.
3. Every sort key, filter key, search field and facet key is checked against the resource. An unknown or disallowed key throws an error naming it.

See [How a request is handled](/start/how-it-works) for the steps that follow.
