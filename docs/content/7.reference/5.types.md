---
title: Type Reference
description: Every type exported from drizzle-resource, grouped by role — request, pagination, response, filters, facets, resource config, engine, strategy, and validation — with what each one actually holds
---

`drizzle-resource` exports 54 types from its root, and the identical set from `drizzle-resource/core`.

All of them are interfaces or type aliases — nothing is a class, and nothing needs a runtime import. Generic parameters named `TField` are always a field-path union, and `TRow` is always a hydrated row type.

---

## Request

| Type                          | What it is                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `QueryRequest`                | The normalized request every stage receives: `pagination`, `sorting`, `filters`, `search`, `context`, optional `facets` |
| `QueryRequestInput`           | The transport form — `QueryRequest` with `QueryPaginationInput` pagination and a deprecated optional `context`          |
| `QuerySearchRequest`          | `{ value: string; fields: string[] }`                                                                                   |
| `QuerySortDescriptor<TField>` | `{ key: TField; dir: "asc" \| "desc" }`                                                                                 |
| `QuerySorting<TField>`        | An array of descriptors, applied left to right                                                                          |

The two request types differ in exactly two keys:

```ts twoslash
import type { QueryRequest, QueryRequestInput } from "drizzle-resource";

const transport: QueryRequestInput = {
  pagination: { pageIndex: 1, pageSize: 25 },
  sorting: [],
  filters: [],
  search: { value: "", fields: [] },
};

const normalized: QueryRequest = {
  ...transport,
  pagination: { mode: "offset", pageIndex: 1, pageSize: 25, count: "exact" },
  context: {},
};
```

Normalization fills `mode` and `count`, then replaces `context` with `{}` — the trusted context travels as a sibling argument, never inside the request.

## Pagination

| Type                    | What it is                                                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `QueryPagination`       | `QueryOffsetPagination \| QueryCursorPagination`, discriminated on `mode`                                                          |
| `QueryOffsetPagination` | `{ mode: "offset"; pageIndex; pageSize; count }` — `pageIndex` is one-based                                                        |
| `QueryCursorPagination` | `{ mode: "cursor"; cursor: string \| null; pageSize; count }`                                                                      |
| `QueryPaginationInput`  | The transport union: `mode` may be omitted on the offset branch, `cursor` and `count` are optional, `pageSize` is required on both |
| `QueryCountMode`        | `"none" \| "exact"`                                                                                                                |

Both normalized shapes carry every key, so a value is assignable to the union without narrowing:

```ts twoslash
import type {
  QueryCursorPagination,
  QueryOffsetPagination,
  QueryPagination,
} from "drizzle-resource";

const offset: QueryOffsetPagination = {
  mode: "offset",
  pageIndex: 1,
  pageSize: 25,
  count: "exact",
};
const cursor: QueryCursorPagination = { mode: "cursor", cursor: null, pageSize: 25, count: "none" };

const accepted: QueryPagination[] = [offset, cursor];
```

A resource accepts only the modes its `pagination.modes` lists, and offset is the sole default — cursor mode has to be opted into.

## Response

| Type                    | What it is                                                                     |
| ----------------------- | ------------------------------------------------------------------------------ |
| `QueryResponse<TRow>`   | `{ rows: TRow[]; pageInfo: QueryPageInfo; facets?: QueryFacetResult[] }`       |
| `QueryIdsResponse<TId>` | `{ ids: TId[]; pageInfo: QueryPageInfo }`                                      |
| `QueryPageInfo`         | `QueryOffsetPageInfo \| QueryCursorPageInfo`                                   |
| `QueryOffsetPageInfo`   | `{ mode: "offset"; pageIndex; pageSize; hasNextPage }` plus the count pair     |
| `QueryCursorPageInfo`   | `{ mode: "cursor"; pageSize; nextCursor: string \| null }` plus the count pair |

`pageInfo` is a double discrimination — first on `mode`, then on `count`:

```ts twoslash
import type { QueryPageInfo } from "drizzle-resource";

export function nextPage(pageInfo: QueryPageInfo) {
  if (pageInfo.mode === "cursor") return pageInfo.nextCursor;
  return pageInfo.hasNextPage ? pageInfo.pageIndex + 1 : null;
}

export function total(pageInfo: QueryPageInfo): number | null {
  return pageInfo.count === "exact" ? pageInfo.rowCount : null;
}
```

Narrowing on `count` is what turns `rowCount` from `number | null` into a plain `number`.

::note
The count pair is a separate alias, `QueryPageCount`, intersected into both page-info shapes: `{ count: "none"; rowCount: null } | { count: "exact"; rowCount: number }`. It is not re-exported from the package root — narrow on `count`, or pull the variant out with `Extract<QueryPageInfo, { count: "exact" }>`.
::

## Filters

| Type                           | What it is                                                                                   |
| ------------------------------ | -------------------------------------------------------------------------------------------- |
| `QueryFilterOperator`          | `contains`, `is`, `isAnyOf`, `isNot`, `gt`, `gte`, `lt`, `lte`, `between`, `before`, `after` |
| `QueryFilterCondition<TField>` | `{ type: "condition"; key: TField; operator; value: unknown }`                               |
| `QueryFilterGroup<TField>`     | `{ type: "group"; combinator: "and" \| "or"; children }`                                     |
| `QueryFilterNode<TField>`      | A condition or a group                                                                       |
| `QueryFilters<TField>`         | `QueryFilterNode<TField>[]` — the type of `request.filters`                                  |
| `QueryFilterInput<TField>`     | What a scope handler may return: a node, an array of nodes, `null`, or `undefined`           |
| `QueryFilterBuilder<TField>`   | The interface `createQueryFilterBuilder` returns                                             |

`value` is always `unknown`, so the operator's expected shape is a runtime contract rather than a type-level one:

```ts twoslash
import type { QueryFilters } from "drizzle-resource";

import type { MyFieldPaths } from "./twoslash-support";

const filters: QueryFilters<MyFieldPaths> = [
  { type: "condition", key: "status", operator: "isAnyOf", value: ["pending", "processing"] },
  {
    type: "group",
    combinator: "or",
    children: [
      { type: "condition", key: "totalAmount", operator: "gte", value: 1000 },
      { type: "condition", key: "isPriority", operator: "is", value: true },
    ],
  },
];
```

Parameterizing with a field-path union is what makes `key` checked — the default `string` accepts anything.

## Facets

| Type                          | What it is                                                                  |
| ----------------------------- | --------------------------------------------------------------------------- |
| `QueryFacetRequest<TField>`   | `{ key: TField; mode?; search?; limit?; cursor? }` — only `key` is required |
| `QueryFacetOption`            | `{ value: unknown; count: number }`                                         |
| `QueryFacetResult<TField>`    | `{ key; options; nextCursor?; total? }`                                     |
| `QueryFacetsResponse<TField>` | `{ facets: QueryFacetResult<TField>[] }`                                    |

`mode` defaults to `exclude-self` when the facet resolver runs, and `nextCursor` is present only when the request set a `limit`.

## Resource configuration

| Type                                    | What it is                                                                                                |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `DefineResourceOptions<…>`              | The second argument to `defineResource`: `relations?`, `query?`, `strategy?`                              |
| `DefineQueryResourceOptions<…>`         | An alias of the above, kept for the `defineQueryResource` name                                            |
| `ResourceQueryConfig<…>`                | The `query` block: `scope`, `search`, `sort`, `filters`, `facets`, `pagination`, `defaults`, `validation` |
| `ResourceQuerySearchConfig<TField>`     | `{ allowed?, defaults? }` — omitting `allowed` makes every registered field searchable                    |
| `ResourceQuerySortConfig<TField>`       | `{ disabled?, defaults? }` — a disabled key throws when a request sorts on it                             |
| `ResourceQueryFiltersConfig<TField>`    | `{ hidden?, disabled? }` — both delete the path from the registry                                         |
| `ResourceQueryFacetsConfig<TField>`     | `{ allowed? }`                                                                                            |
| `ResourceQueryPaginationConfig`         | `{ modes? }` — defaults to `["offset"]`                                                                   |
| `ResourceQueryDefaultsConfig`           | `{ pagination?, sorting? }`, applied when a request leaves them empty                                     |
| `ResourceQueryPaginationDefaultsConfig` | `{ mode?, pageIndex?, pageSize?, count? }`                                                                |

Every one of these is generic over the resource's field-path union, which is why a typo in `allowed` or `hidden` fails to compile.

## Engine and registry

| Type                             | What it is                                                                                                                              |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `QueryEngine<…>`                 | What `createQueryEngine` returns: `withContext`, `defineScope`, `defineResource`, `defineQueryResource`                                 |
| `QueryEngineConfig<…>`           | `{ db, schema, relations }`                                                                                                             |
| `QueryEngineDb`                  | The structural minimum for `db` — `query.<table>.findMany(args?)`                                                                       |
| `QueryEngineSchema`              | A Drizzle schema object keyed by table name                                                                                             |
| `QueryEngineRelations`           | The relation graph, each relation carrying `targetTableName` and `relationType`                                                         |
| `QueryResource<…>`               | A defined resource: `key`, `schema`, `relationGraph`, `relations`, `fields`, `queryConfig`, and the four methods                        |
| `QueryRootKey<TDb, TSchema>`     | Table names present in both `db.query` and the schema                                                                                   |
| `QueryWith<TDb, TSchema, TRoot>` | The relational `with` tree a root table accepts                                                                                         |
| `QueryRowShape<…>`               | The root row type, without relations                                                                                                    |
| `QueryResultRowShape<…>`         | The hydrated row type for a given `with` tree                                                                                           |
| `QueryFieldPath<…>`              | The dotted field-path union for a root and `with` tree                                                                                  |
| `FieldRegistryEntry`             | One registry row: `path`, `source`, `column`, `tableName`, `relationPath`, `firstManyIndex`, `outerJoinSteps`, `isManyPath`, `sortable` |
| `FieldRegistryRelationStep`      | One relation hop inside a path                                                                                                          |

`QueryFieldPath` is the type behind every checked key. It walks four relation steps by default, and the fourth parameter is the same `with` tree the resource declares:

```ts twoslash
import type { QueryFieldPath } from "drizzle-resource";

import type { relations, schema } from "./twoslash-support";

export type OrdersFieldPath = QueryFieldPath<
  typeof schema,
  typeof relations,
  "orders",
  { customer: true }
>;

const sortKey: OrdersFieldPath = "customer.name";
```

Declaring a narrower `with` tree yields a narrower union — field paths follow the relations you actually hydrate.

`QueryResultRowShape` derives the row type from the same four inputs, which is how `rows` stays typed without a manual interface:

```ts twoslash
import type { QueryResultRowShape } from "drizzle-resource";

import type { db, relations, schema } from "./twoslash-support";

export type OrderWithCustomer = QueryResultRowShape<
  typeof db,
  typeof schema,
  typeof relations,
  "orders",
  { customer: true }
>;

const customerName: OrderWithCustomer["customer"]["name"] = "Acme Corp";
```

A `one` relation resolves to an object, a `many` relation to an array — the cardinality comes from the relation graph, not from the `with` tree.

The registry itself is a `Map` on the resource, so `FieldRegistryEntry` is readable at runtime:

```ts twoslash
import { ordersResource } from "./twoslash-support";
// ---cut-before---
const entry = ordersResource.fields.get("orderLines.product.name");

const plan = {
  sortable: entry?.sortable,
  isManyPath: entry?.isManyPath,
  steps: entry?.relationPath.map((step) => `${step.relationName}:${step.relationType}`),
};
```

`isManyPath` is `true` here, which is why the path is non-sortable and compiles to an `EXISTS` subquery.

## Strategy

| Type                             | What it is                                                    |
| -------------------------------- | ------------------------------------------------------------- |
| `ResourceQueryStrategyConfig<…>` | The four optional overrides: `query`, `ids`, `rows`, `facets` |
| `QueryResourceUtils<TRow>`       | The twelve helpers handed to every override                   |

`QueryResourceUtils` is the one strategy type worth naming explicitly — it lets you extract logic out of an inline override:

```ts twoslash
import type { QueryRequest, QueryResourceUtils } from "drizzle-resource";

import type { OrderRow } from "./twoslash-support";

export function filterNodeCount(request: QueryRequest, utils: QueryResourceUtils<OrderRow>) {
  return utils.normalizeFilters(request.filters).children.length;
}
```

Every helper's signature is fixed by `TRow`, so `executeRowsQuery` resolves to `OrderRow[]` in the function above.

::note
The per-stage argument interfaces — `ResourceQueryStrategyIdsArgs`, `ResourceQueryStrategyRowsArgs`, `ResourceQueryStrategyFacetsArgs` — are not exported. Write overrides inline so their arguments infer, and type extracted helpers against `QueryRequest` and `QueryResourceUtils` instead.
::

## Validation

| Type                                 | What it is                                                                                                                        |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `ResourceQueryValidationConfig`      | The six optional ceilings: `maxPageSize`, `maxCursorLength`, `maxFilterDepth`, `maxFilterNodes`, `maxFacetCount`, `maxFacetLimit` |
| `QueryRequestSchemaOverride<TField>` | A validator-local restriction: `{ defaults?, limits?, allow? }`                                                                   |
| `QueryRequestContract<TField>`       | The resolved policy a validator consumes                                                                                          |

`QueryRequestContract` is what `resolveQueryRequestContract` returns — five `Set`s, the merged defaults, and fully resolved limits:

```ts twoslash
import type { QueryRequestContract } from "drizzle-resource";
import { resolveQueryRequestContract } from "drizzle-resource/core";

import { ordersResource } from "./twoslash-support";

const contract: QueryRequestContract = resolveQueryRequestContract(ordersResource);

const sortableKeys = [...contract.sorting].sort();
```

`limits` is `Required<ResourceQueryValidationConfig>` on the contract, so every ceiling has a value once it is resolved.

## Types you cannot import

Eight types are declared in the source but left out of the public export list. Each has a supported substitute:

| Internal type                                                                                      | Use instead                                                        |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `QueryPageCount`                                                                                   | `Extract<QueryPageInfo, { count: "exact" }>`, or narrow on `count` |
| `QueryScopeHandler`                                                                                | Declare `scope` inline in `query`, where both arguments infer      |
| `QueryRelationsConfig`                                                                             | The literal `relations` tree, declared `as const`                  |
| `ResourceQueryStrategyIdsArgs`, `ResourceQueryStrategyRowsArgs`, `ResourceQueryStrategyFacetsArgs` | `QueryRequest` plus `QueryResourceUtils<TRow>`                     |
| `ResourceRuntimeQueryConfig`                                                                       | `resource.queryConfig`, read through `typeof`                      |
| `GenericObject`                                                                                    | `Record<string, unknown>`                                          |
