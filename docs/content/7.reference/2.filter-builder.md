`createQueryFilterBuilder` returns a typed DSL that builds `QueryFilterNode` trees. It produces plain JSON — the same nodes a client sends over the wire.

## `createQueryFilterBuilder<TField>()`

Pass the resource's field-path union as the type argument, and every key is checked at compile time:

```ts twoslash
import { createQueryFilterBuilder } from "drizzle-resource";

import type { MyFieldPaths } from "./twoslash-support";

const f = createQueryFilterBuilder<MyFieldPaths>();

const orgFilter = f.is("customer.orgId", "acme");
```

`MyFieldPaths` is derived with `QueryFieldPath`, so the builder's autocomplete is the field registry itself.

A path the resource never registered fails to compile:

```ts twoslash
// @errors: 2345
import { f } from "./twoslash-support";
// ---cut-before---
f.is("customer.email", "ada@example.com");
```

Inside `query.scope` the builder arrives pre-typed, so you rarely construct one by hand.

## Method summary

| Method                           | Value it expects       | Compiles to                                                  |
| -------------------------------- | ---------------------- | ------------------------------------------------------------ |
| `contains(key, value)`           | scalar                 | `lower(col) LIKE '%value%'`                                  |
| `is(key, value)`                 | scalar                 | `lower(col) = 'value'` on text, `col = value` otherwise      |
| `isNot(key, value)`              | scalar                 | the negation of `is`                                         |
| `isAnyOf(key, value)`            | array                  | `or(col = a, col = b, …)`                                    |
| `gt` · `gte` · `lt` · `lte`      | scalar                 | `col > value`, `col >= value`, `col < value`, `col <= value` |
| `between(key, value)`            | `{ from?, to? }`       | `col between from and to`                                    |
| `before` · `after`               | scalar                 | aliases of `lt` and `gt`                                     |
| `and(children)` · `or(children)` | `QueryFilterNode[]`    | a `group` node                                               |
| `condition(node)`                | `QueryFilterCondition` | the node, unchanged                                          |

Only `between` constrains its value at the type level. Every other method declares `value: unknown`, so a wrong value type surfaces as wrong SQL rather than a compile error.

Every condition method follows the same shape — a key, then a value:

```ts twoslash
import { f } from "./twoslash-support";
// ---cut-before---
const conditions = [
  f.contains("customer.name", "acme"),
  f.is("status", "shipped"),
  f.isNot("status", "cancelled"),
  f.isAnyOf("status", ["pending", "processing"]),
  f.gt("totalAmount", 100),
  f.gte("totalAmount", 100),
  f.lt("totalAmount", 5000),
  f.lte("totalAmount", 5000),
  f.between("createdAt", { from: new Date("2026-01-01"), to: new Date("2026-01-31") }),
  f.before("createdAt", new Date("2026-06-01")),
  f.after("createdAt", new Date("2026-01-01")),
];
```

Each call returns a `QueryFilterCondition<TField>`, so the array above has a single element type.

## Text matching

`contains` lowercases both sides — `lower(col) LIKE lower('%value%')`. Non-text columns are cast to text first, so `contains` works on a numeric reference or a uuid.

`is` and `isNot` are also **case-insensitive** on text columns. A boolean value compiles to `col = true` or `col = false`, and an array value silently collapses to `value[0]`.

::note
There is no `ILIKE` anywhere in the compiler. Index accordingly — a plain B-tree on a text column never serves these predicates. See [Optimization](/performance/optimization).
::

## `isAnyOf`

`isAnyOf` expands to a disjunction of equalities, not to `IN (…)`:

```ts twoslash
import { f, utils } from "./twoslash-support";
// ---cut-before---
const predicate = utils.compileFilterNode(f.isAnyOf("status", ["pending", "processing"]));
```

Each element is compared the way `is` compares it, so text elements match case-insensitively.

::warning
An empty array compiles to a constant `false` predicate and matches **nothing**. Drop the condition instead of sending `isAnyOf` with `[]` when a multi-select filter is cleared.
::

A non-array value is accepted and behaves exactly like `is`.

## Ordered comparisons

`gt`, `gte`, `lt`, and `lte` emit the raw comparison with no normalization. On a text column they are therefore **case-sensitive**, unlike `is` and `contains`.

`before` and `after` are aliases — `before` compiles identically to `lt`, `after` identically to `gt`. Use them when the field is temporal and the intent reads better.

## `between`

`between` takes an object with optional `from` and `to` bounds. Both bounds present produce an inclusive `BETWEEN`:

```ts twoslash
import { f } from "./twoslash-support";
// ---cut-before---
const openEnded = f.between("createdAt", { from: new Date("2026-01-01") });
```

A one-sided range is fully supported: `from` alone compiles to `>=`, `to` alone to `<=`.

| Value          | SQL                       | Matches                       |
| -------------- | ------------------------- | ----------------------------- |
| `{ from, to }` | `col between from and to` | the inclusive range           |
| `{ from }`     | `col >= from`             | everything at or after `from` |
| `{ to }`       | `col <= to`               | everything at or before `to`  |
| `{}`           | `true`                    | every row                     |
| `[from, to]`   | `false`                   | nothing                       |

An array is the trap. It is a compile error through the builder, and a silent `false` when it arrives as JSON:

```ts twoslash
// @errors: 2559
import { f } from "./twoslash-support";
// ---cut-before---
f.between("totalAmount", [100, 500]);
```

Validate the payload shape at the edge — `requestSchema` types `value` as `unknown`, so an array reaches the compiler intact.

## Groups

`and` and `or` wrap child nodes into a `group`. Nest them to any depth the request limits allow:

```ts twoslash
import { f } from "./twoslash-support";
// ---cut-before---
const tree = f.and([
  f.isNot("status", "cancelled"),
  f.or([
    f.gte("totalAmount", 1000),
    f.and([f.is("isPriority", true), f.after("createdAt", new Date("2026-01-01"))]),
  ]),
]);
```

A group with no children compiles to `true` regardless of its combinator, so an empty `and([])` is a safe no-op.

`condition` passes an existing node straight through, which lets you mix stored filters with freshly built ones:

```ts twoslash
import type { QueryFilterCondition } from "drizzle-resource";

import { f, type MyFieldPaths } from "./twoslash-support";

const stored: QueryFilterCondition<MyFieldPaths> = {
  type: "condition",
  key: "orderLines.product.category",
  operator: "is",
  value: "electronics",
};

const reused = f.and([f.condition(stored), f.is("status", "shipped")]);
```

The builder validates nothing at runtime — an unknown key throws later, during normalization.

## In a scope function

`query.scope` receives the builder as its first argument and the typed context as its second:

```ts twoslash
import { engine } from "./twoslash-support";
// ---cut-before---
export const scopedOrders = engine.defineResource("orders", {
  relations: { customer: true, orderLines: { with: { product: true } } },
  query: {
    scope: (filters, ctx) =>
      ctx.isAdmin
        ? []
        : filters.and([
            filters.is("customer.orgId", ctx.orgId),
            filters.isNot("status", "archived"),
          ]),
  },
});
```

Returning `[]` merges nothing, which is how an admin bypass is written.

::caution
A scope filter may not reference a hidden or disabled path. Both settings delete the field from the registry, and the merged node then throws `Unknown filter field` on every request. See [Scope Rules](/resource-setup/scope).
::

## In a strategy

Strategies receive the already-merged `request.filters`. Append to that array rather than replacing it, or the scope is lost:

```ts twoslash
import { engine, f } from "./twoslash-support";
// ---cut-before---
export const recentOrders = engine.defineResource("orders", {
  relations: { customer: true },
  strategy: {
    ids: ({ request, utils }) =>
      utils.executeIdsQuery({
        request: {
          ...request,
          filters: [...request.filters, f.between("createdAt", { from: new Date("2026-01-01") })],
        },
      }),
  },
});
```

Nodes added inside a strategy skip field-policy validation, so they may reference paths a client cannot.
