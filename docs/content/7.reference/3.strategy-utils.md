title: Strategy Utils
description: All twelve helpers on the utils object passed to every strategy override — the string and tree normalizers, the SQL compilers, and the built-in ids, rows, page, and facet executors
---

Every strategy override receives `utils`, a `QueryResourceUtils<TRow>` bound to this resource's field registry and Drizzle connection.

The object has twelve members. Eight are synchronous; four run SQL.

| Member                                | Returns                                 |
| ------------------------------------- | --------------------------------------- |
| `normalizeString(value)`              | `string`                                |
| `normalizeFilters(filters)`           | `QueryFilterGroup`                      |
| `compileCondition(condition)`         | `SQL`                                   |
| `compileFilterNode(node)`             | `SQL`                                   |
| `compileSearch(search)`               | `SQL \| undefined`                      |
| `compileOrderBy(sorting)`             | `Array<SQL \| PgColumn \| SQL.Aliased>` |
| `buildWhereClause(request)`           | `SQL \| undefined`                      |
| `executeIdsQuery({ request })`        | `Promise<QueryIdsResponse<TId>>`        |
| `executeRowsQuery({ ids, request? })` | `Promise<TRow[]>`                       |
| `executeHydratedPage({ request })`    | `Promise<QueryResponse<TRow>>`          |
| `resolveFacets({ request, facets })`  | `Promise<QueryFacetsResponse>`          |
| `resolveField(path)`                  | `FieldRegistryEntry \| undefined`       |

The request a strategy receives is already normalized — scope merged, defaults applied, limits and field policy asserted. Every helper assumes that.

::note
One `utils` object is built per resource and reused for every request, so holding a reference to it is safe.
::

## Normalizers

### `utils.normalizeString(value)`

Lowercase any value the way the filter compiler does, so client input and bucket values compare consistently:

```ts twoslash
import { result, utils } from "./twoslash-support";
// ---cut-before---
const selected = ["Pending", "SHIPPED"].map((value) => utils.normalizeString(value));

const selectedBuckets = result.facets
  .flatMap((facet) => facet.options)
  .filter((option) => selected.includes(utils.normalizeString(option.value)));
```

`null` and `undefined` both normalize to the empty string, so the comparison never throws.

**Returns:** `string` — `String(value ?? "").toLowerCase()`.

### `utils.normalizeFilters(filters)`

Collapse a request's top-level filter array into the single root `and` group the compiler expects:

```ts twoslash
import { f, request, utils } from "./twoslash-support";
// ---cut-before---
const root = utils.normalizeFilters([...request.filters, f.is("status", "shipped")]);

const predicate = utils.compileFilterNode(root);
```

An array is wrapped, an existing `and` group passes through unchanged, and any other node is nested inside a fresh `and`.

**Returns:** `QueryFilterGroup` — always a group, never `undefined`.

## SQL compilers

### `utils.compileCondition(condition)`

Compile one condition node against the field registry, then combine it with SQL of your own:

```ts twoslash
import { and, orders, sql, utils } from "./twoslash-support";
// ---cut-before---
const priority = utils.compileCondition({
  type: "condition",
  key: "isPriority",
  operator: "is",
  value: true,
});

const urgent = and(priority, sql`${orders.createdAt} > now() - interval '7 days'`);
```

A condition on a `many` path compiles to an `EXISTS` subquery; a `one` path resolves through the joins the registry recorded.

**Returns:** `SQL`. An unrecognized `key` yields a `true` predicate rather than an error, because the engine validated keys before the strategy ran.

### `utils.compileFilterNode(node)`

Compile a whole tree — conditions, groups, and nested groups — in one call:

```ts twoslash
import { f, utils } from "./twoslash-support";
// ---cut-before---
const predicate = utils.compileFilterNode(
  f.or([f.is("status", "pending"), f.is("status", "processing")]),
);
```

A group with no children compiles to `true`, so an empty tree never removes rows.

**Returns:** `SQL`.

### `utils.compileSearch(search)`

Compile the free-text search into an `or` of `contains` predicates across `search.fields`:

```ts twoslash
import { and, orders, request, sql, utils } from "./twoslash-support";
// ---cut-before---
const searchPredicate = utils.compileSearch(request.search);

const visible = and(searchPredicate, sql`${orders.deletedAt} is null`);
```

Drizzle's `and` accepts the `undefined` case, so no branch is needed when the user typed nothing.

**Returns:** `SQL | undefined` — `undefined` when `search.value` is empty or no fields resolved.

### `utils.compileOrderBy(sorting)`

Turn sort descriptors into Drizzle `orderBy` arguments:

```ts twoslash
import { desc, orders, request, utils } from "./twoslash-support";
// ---cut-before---
const orderBy = utils.compileOrderBy(request.sorting);

const ordering = orderBy.length > 0 ? orderBy : [desc(orders.createdAt)];
```

Keys that are unknown or non-sortable are dropped silently, so supply your own fallback when the result can be empty.

**Returns:** `Array<SQL | PgColumn | SQL.Aliased<unknown>>`, memoized per sorting shape.

### `utils.buildWhereClause(request)`

Pass the **whole request** — the helper reads `filters` and `search` itself:

```ts twoslash
import type { QueryRequest } from "drizzle-resource";

import { and, orders, sql, utils } from "./twoslash-support";

export function visibleWhere(request: QueryRequest) {
  return and(utils.buildWhereClause(request), sql`${orders.deletedAt} is null`);
}
```

The result already contains the scope filters, because scope merging happens during normalization.

**Returns:** `SQL | undefined`. In practice it is always defined — an empty filter tree still compiles to `true`.

## Executors

### `utils.executeIdsQuery({ request })`

Run the built-in ids stage: a `matching_ids` CTE, the count query when `count: "exact"`, then the paginated select.

Wrap it when you want the default SQL plus one extra condition:

```ts twoslash
import { engine, f } from "./twoslash-support";
// ---cut-before---
export const activeOrders = engine.defineResource("orders", {
  strategy: {
    ids: ({ request, utils }) =>
      utils.executeIdsQuery({
        request: { ...request, filters: [...request.filters, f.isNot("status", "cancelled")] },
      }),
  },
});
```

The argument object takes `request` and nothing else — there is no `context` parameter, since the context has already shaped the request's scope filters.

**Returns:** `Promise<QueryIdsResponse<TId>>` — `{ ids, pageInfo }`, with `pageInfo` matching the request's mode and count policy.

### `utils.executeRowsQuery({ ids, request? })`

Hydrate an ordered id list through the resource's declared relations:

```ts twoslash
import { request, utils } from "./twoslash-support";
// ---cut-before---
const { ids, pageInfo } = await utils.executeIdsQuery({ request });
const rows = await utils.executeRowsQuery({ ids, request });

const page = { rows, pageInfo };
```

Those two calls are the whole default pipeline, which is why `rows` is the array itself rather than a wrapper object.

**Returns:** `Promise<TRow[]>`. Ids are deduplicated, the output is re-sorted to match the input order, and an empty list resolves to `[]` without a query.

::caution
Hydration filters on `id` only — `request` is accepted for symmetry but adds no predicate. Never hand it ids that did not come from a scoped ids query.
::

### `utils.executeHydratedPage({ request })`

Run the ids stage and the rows stage together, then add anything the built-in pipeline leaves out:

```ts twoslash
import { engine } from "./twoslash-support";
// ---cut-before---
export const ordersWithFacets = engine.defineResource("orders", {
  relations: { customer: true },
  strategy: {
    query: async ({ request, utils }) => {
      const page = await utils.executeHydratedPage({ request });
      if (!request.facets?.length) return page;

      const { facets } = await utils.resolveFacets({ request, facets: request.facets });
      return { ...page, facets };
    },
  },
});
```

Hydration is skipped when the ids stage returns nothing, so an empty page still costs one query.

**Returns:** `Promise<QueryResponse<TRow>>` — `{ rows, pageInfo }`. Facets are never included.

### `utils.resolveFacets({ request, facets })`

Resolve bucket counts with the built-in facet engine:

```ts twoslash
import { request, utils } from "./twoslash-support";
// ---cut-before---
const { facets } = await utils.resolveFacets({
  request,
  facets: [{ key: "status", mode: "exclude-self", limit: 10 }],
});

const statusBuckets = facets[0]?.options ?? [];
```

Facets sharing a scoped request share one `matchingIds` CTE, so a second facet on the same scope adds a query but not a re-scan.

Each bucket count is `count(distinct id)`, the `total` comes from a `count(*) over ()` window in the same query, and buckets are ordered by count descending then value ascending. Null values are dropped, and `mode` defaults to `exclude-self`.

**Returns:** `Promise<QueryFacetsResponse>` — `{ facets }`. `nextCursor` is `undefined` when the facet had no `limit`.

## Registry access

### `utils.resolveField(path)`

Look up what the engine knows about a dotted path:

```ts twoslash
import { utils } from "./twoslash-support";
// ---cut-before---
const entry = utils.resolveField("orderLines.product.name");

const usesExistsSubquery = entry?.isManyPath ?? false;
```

`entry.column` is the Drizzle column, `entry.sortable` tells you whether `compileOrderBy` will keep it, and `entry.relationPath` lists the joins that reach it.

**Returns:** `FieldRegistryEntry | undefined` — `undefined` for a path that is hidden, disabled, or never registered.
