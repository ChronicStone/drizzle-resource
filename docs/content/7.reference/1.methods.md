---
title: Query Methods
description: The four methods on a defined resource — query, queryIds, queryRows, queryFacets — with their exact arguments and return types, including the plain array queryRows resolves to
---

`engine.defineResource` returns an object carrying four query methods. Each one takes a `QueryRequestInput` and an optional typed `context`.

| Method        | Resolves to                      | Stages                       |
| ------------- | -------------------------------- | ---------------------------- |
| `query`       | `QueryResponse<TRow>`            | normalize, ids, rows, facets |
| `queryIds`    | `QueryIdsResponse<TId>`          | normalize, ids               |
| `queryRows`   | `TRow[]`                         | normalize, rows              |
| `queryFacets` | `QueryFacetsResponse<TFacetKey>` | normalize, facets            |

Every method normalizes the request first — scope merge, defaults, limits, field policy. A rejected request throws a plain `Error` before any SQL is built.

## Shared arguments

::field-group
::field{name="request" type="QueryRequestInput" required}
The client payload. `pagination`, `sorting`, `filters`, and `search` are required by the type; `facets` is optional. See [Request Shape](/query-contract/request-shape).
::

::field{name="context" type="TContext"}
Server-derived state handed to `query.scope`. Typed by `engine.withContext<…>()` and never read from the request body.
::
::

`queryRows` adds a required `ids` array, and `queryFacets` adds a required `facets` array. Neither method reads `request.facets`.

## `resource.query({ request, context })`

Use `query` for the full pipeline — ids, hydration, and any requested facets in one call:

```ts twoslash
import { ordersResource } from "./twoslash-support";
// ---cut-before---
const { rows, pageInfo, facets } = await ordersResource.query({
  context: { orgId: "acme" },
  request: {
    pagination: { mode: "offset", pageIndex: 1, pageSize: 25, count: "exact" },
    sorting: [{ key: "createdAt", dir: "desc" }],
    search: { value: "laptop", fields: [] },
    filters: [],
    facets: [{ key: "status", mode: "exclude-self", limit: 10 }],
  },
});
```

Facets resolve only when `request.facets` is non-empty — the call above adds one query per requested facet.

::field-group
::field{name="rows" type="TRow[]" required}
The hydrated page, typed from the schema and the resource's declared relations, in the order the ids stage produced.
::

::field{name="pageInfo" type="QueryPageInfo" required}
Pagination metadata discriminated on `mode`. Narrow before reading `pageIndex`, `hasNextPage`, or `nextCursor`.
::

::field{name="facets" type="QueryFacetResult[]"}
Present only when the request asked for facets. Absent — not empty — otherwise.
::
::

The filtered total lives at `pageInfo.rowCount` and is `null` unless the request set `count: "exact"`.

## `resource.queryIds({ request, context })`

Use `queryIds` when you want the page's primary keys without paying for hydration:

```ts twoslash
import { ordersResource, requestInput } from "./twoslash-support";
// ---cut-before---
const { ids, pageInfo } = await ordersResource.queryIds({
  context: { orgId: "acme" },
  request: requestInput,
});

const cacheKey = `orders:${pageInfo.pageSize}:${ids.join(",")}`;
```

The returned `pageInfo` is identical to the one `query` produces for the same request, so an id page can be cached and hydrated later without running the ids stage again.

::field-group
::field{name="ids" type="TId[]" required}
Ordered primary keys for the page. `TId` is inferred from the row's `id` column.
::

::field{name="pageInfo" type="QueryPageInfo" required}
The same metadata `query` returns, including `nextCursor` in cursor mode.
::
::

## `resource.queryRows({ request, ids, context })`

Use `queryRows` to hydrate an id list you already hold:

```ts twoslash
import { ids, ordersResource, requestInput, type OrderRow } from "./twoslash-support";
// ---cut-before---
const rows: OrderRow[] = await ordersResource.queryRows({
  context: { orgId: "acme" },
  request: requestInput,
  ids,
});

const references = rows.map((row) => row.reference);
```

The annotation above compiles because the method resolves to the array itself.

::note
`queryRows` resolves to `TRow[]`, not `{ rows }`. The same is true of `strategy.rows` and `utils.executeRowsQuery`.
::

Hydration deduplicates the ids, issues one relational query, and re-sorts the result to match the order you passed. Ids that no longer exist are dropped, so the array can be shorter than the input.

::caution
Hydration matches on `id` alone — scope filters are not re-applied. Only pass ids that came from `queryIds` on the same resource and context, never ids taken from a request body.
::

## `resource.queryFacets({ request, facets, context })`

Use `queryFacets` when the facet sidebar loads on its own schedule:

```ts twoslash
import { ordersResource, requestInput } from "./twoslash-support";
// ---cut-before---
const { facets } = await ordersResource.queryFacets({
  context: { orgId: "acme" },
  request: requestInput,
  facets: [
    { key: "status", mode: "exclude-self", limit: 10 },
    { key: "tags.name", mode: "include-self", search: "prio", limit: 20 },
  ],
});

const statusOptions = facets.find((facet) => facet.key === "status")?.options ?? [];
```

The `facets` argument infers `TFacetKey`, so every returned `key` is typed as one of the keys you asked for.

::field-group
::field{name="facets" type="QueryFacetResult[]" required}
One entry per requested key, each with `options`, an optional `total`, and an optional `nextCursor`. Null bucket values are filtered out.
::
::

The request still runs the full normalize stage, so scope filters constrain the buckets exactly as they constrain the page.
