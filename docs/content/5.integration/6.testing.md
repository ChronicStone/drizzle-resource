title: Unit Testing
description: Assert scope enforcement with a capturing strategy, prove denied field paths throw, and exercise the real ids pipeline against a chainable fake database.
---

Scope enforcement is the one behavior worth a test on every resource. A missing tenant filter is a data leak, not a bug — and it is invisible in a passing feature test that only ever runs as one organization.

Two techniques cover almost everything, and neither needs Postgres:

| Technique                    | Proves                                                    | Cost          |
| ---------------------------- | --------------------------------------------------------- | ------------- |
| A capturing `strategy.query` | scope merge, normalization, policy rejections             | no SQL at all |
| A chainable fake `db`        | the built-in ids pipeline, cursor lookahead, count policy | no database   |

## Capturing the normalized request

Define the resource with a `strategy.query` that records the request it receives and returns a fixed page. The engine still runs scope merging, normalization, and every assertion — it just never reaches SQL:

```ts twoslash [orders.fixture.ts]
import { createQueryEngine } from "drizzle-resource";
import type { QueryRequest } from "drizzle-resource";

import { relations } from "./relations";
import { schema } from "./schema";

/** `findMany` is never called, but the engine's types require it. */
const fakeDb = { query: { orders: { findMany: async () => [] } } };

export function createOrdersFixture() {
  const captured: QueryRequest[] = [];

  const resource = createQueryEngine({ db: fakeDb, schema, relations })
    .withContext<{ isAdmin?: boolean; orgId: string }>()
    .defineResource("orders", {
      relations: { customer: true },
      query: {
        filters: { disabled: ["deletedAt"] },
        scope: (f, ctx) => (ctx.isAdmin ? undefined : f.is("customer.orgId", ctx.orgId)),
        sort: { defaults: [{ dir: "desc", key: "createdAt" }] },
      },
      strategy: {
        query: async ({ request }) => {
          captured.push(request);
          return {
            rows: [],
            pageInfo: {
              mode: "offset",
              pageIndex: 1,
              pageSize: 25,
              hasNextPage: false,
              count: "exact",
              rowCount: 0,
            },
          };
        },
      },
    });

  return { captured, resource };
}

/** A minimal valid payload for tests that only care about one key. */
export const baseRequest = {
  filters: [],
  pagination: { mode: "offset", pageIndex: 1, pageSize: 25 },
  search: { fields: [], value: "" },
  sorting: [],
} as const;
```

`captured` holds the exact `QueryRequest` a strategy would compile, which is the boundary where a scope bug becomes observable.

## Asserting scope enforcement

Three assertions cover the security-critical contract. The runner is interchangeable — this uses `vitest` shapes:

```ts [orders.scope.test.ts]
import { describe, expect, it } from "vitest";

import { baseRequest, createOrdersFixture } from "./orders.fixture";

describe("orders scope", () => {
  it("prepends the tenant filter ahead of client filters", async () => {
    const { captured, resource } = createOrdersFixture();

    await resource.query({
      context: { orgId: "acme" },
      request: {
        ...baseRequest,
        filters: [{ type: "condition", key: "status", operator: "is", value: "pending" }],
      },
    });

    expect(captured[0]?.filters).toEqual([
      { type: "condition", key: "customer.orgId", operator: "is", value: "acme" },
      { type: "condition", key: "status", operator: "is", value: "pending" },
    ]);
  });

  it("ignores context sent in the request body", async () => {
    const { captured, resource } = createOrdersFixture();

    await resource.query({
      context: { orgId: "acme" },
      request: { ...baseRequest, context: { orgId: "other-org" } },
    });

    expect(captured[0]?.context).toEqual({});
    expect(captured[0]?.filters[0]).toMatchObject({ value: "acme" });
  });

  it("drops the scope filter for an admin context", async () => {
    const { captured, resource } = createOrdersFixture();

    await resource.query({ context: { isAdmin: true, orgId: "acme" }, request: baseRequest });

    expect(captured[0]?.filters).toEqual([]);
  });
});
```

The first assertion is the important one. Scope is prepended at index `0`, and client filters are appended after it — a client can add conditions but can never remove, reorder, or `or` its way around the tenant filter.

The second closes the other half of the hole. The engine overwrites `request.context` with `{}` during normalization, so a body carrying `context` cannot reach the scope function even when no validator ran.

::warning
Test the admin bypass in both directions. A scope function returning `undefined` removes tenancy entirely, so a test that only checks the admin path passing would not notice `isAdmin` defaulting to `true`.
::

## Asserting the denied surface throws

Every field-policy decision is observable as a rejection. Assert the real message rather than a copy of it, so a reworded message fails the test instead of silently passing:

```ts [orders.policy.test.ts]
import { describe, expect, it } from "vitest";

import { baseRequest, createOrdersFixture } from "./orders.fixture";

describe("orders field policy", () => {
  it("rejects a disabled filter path", async () => {
    const { resource } = createOrdersFixture();

    await expect(
      resource.query({
        context: { orgId: "acme" },
        request: {
          ...baseRequest,
          filters: [{ type: "condition", key: "deletedAt", operator: "is", value: null }],
        },
      }),
    ).rejects.toThrow('Unknown filter field "deletedAt" for resource "orders"');
  });

  it("rejects sorting through a many relation", async () => {
    const { resource } = createOrdersFixture();

    await expect(
      resource.query({
        context: { orgId: "acme" },
        request: { ...baseRequest, sorting: [{ key: "tags.name", dir: "asc" }] },
      }),
    ).rejects.toThrow('Sorting field "tags.name" is not allowed for resource "orders"');
  });

  it("rejects a page size above the limit", async () => {
    const { resource } = createOrdersFixture();

    await expect(
      resource.query({
        context: { orgId: "acme" },
        request: { ...baseRequest, pagination: { pageIndex: 1, pageSize: 500 } },
      }),
    ).rejects.toThrow("Page size cannot exceed 100");
  });
});
```

Note the first message. A `disabled` path is removed from the registry, so it reports as **unknown** rather than as forbidden — the same message a typo produces.

These tests are also where the error-mapping helper earns its keep. Asserting the thrown message here and reusing the same strings in [Error Handling](/integration/error-handling) keeps the mapping honest across upgrades.

## Testing against a fake database

Drop the strategy to exercise the built-in pipeline. The engine needs `db.query.<table>.findMany` for hydration, plus `$with`, `with`, and `selectDistinct` for the ids and facet stages, and each builder method must return something chainable:

```ts twoslash [fake-db.ts]
import { orders } from "./schema";

interface QueryTrace {
  countQueries: number;
  limits: number[];
  offsets: number[];
}

export function createFakeDb(pages: Array<Array<Record<string, unknown>>>, rowCount = 0) {
  const trace: QueryTrace = { countQueries: 0, limits: [], offsets: [] };

  class Builder implements PromiseLike<Array<Record<string, unknown>>> {
    constructor(private readonly rows: Array<Record<string, unknown>>) {}
    from() {
      return this;
    }
    innerJoin() {
      return this;
    }
    where() {
      return this;
    }
    orderBy() {
      return this;
    }
    limit(value: number) {
      trace.limits.push(value);
      return this;
    }
    offset(value: number) {
      trace.offsets.push(value);
      return this;
    }
    then<TResolved = Array<Record<string, unknown>>, TRejected = never>(
      onfulfilled?:
        ((value: Array<Record<string, unknown>>) => TResolved | PromiseLike<TResolved>) | null,
      onrejected?: ((reason: unknown) => TRejected | PromiseLike<TRejected>) | null,
    ): PromiseLike<TResolved | TRejected> {
      return Promise.resolve(this.rows).then(onfulfilled, onrejected);
    }
  }

  const db = {
    query: {
      orders: {
        findMany: async ({ where }: { where: { id: { in: string[] } } }) =>
          where.id.in.map((id) => ({ id, reference: `ORD-${id}` })),
      },
    },
    selectDistinct: () => new Builder([]),
    $with: () => ({ as: () => ({ id: orders.id }) }),
    with: () => ({
      select: (selection: Record<string, unknown>) => {
        if ("rowCount" in selection) {
          trace.countQueries += 1;
          return new Builder([{ rowCount }]);
        }
        return new Builder(pages.shift() ?? []);
      },
    }),
  };

  return { db, trace };
}
```

`Builder` implements `PromiseLike`, which is what lets the engine `await` a query chain without a real driver. `pages` is a queue — each ids query shifts the next page of stub rows off the front.

Two details make the stub rows realistic. The ids stage selects `id` plus one `__cursor_<n>` alias per sort descriptor, and the count query is the only `select` whose selection contains `rowCount`:

```ts twoslash [cursor-pipeline.test.ts]
import { orders } from "./schema";

interface QueryTrace {
  countQueries: number;
  limits: number[];
  offsets: number[];
}

function createFakeDb(pages: Array<Array<Record<string, unknown>>>, rowCount = 0) {
  const trace: QueryTrace = { countQueries: 0, limits: [], offsets: [] };

  class Builder implements PromiseLike<Array<Record<string, unknown>>> {
    constructor(private readonly rows: Array<Record<string, unknown>>) {}
    from() {
      return this;
    }
    innerJoin() {
      return this;
    }
    where() {
      return this;
    }
    orderBy() {
      return this;
    }
    limit(value: number) {
      trace.limits.push(value);
      return this;
    }
    offset(value: number) {
      trace.offsets.push(value);
      return this;
    }
    then<TResolved = Array<Record<string, unknown>>, TRejected = never>(
      onfulfilled?:
        ((value: Array<Record<string, unknown>>) => TResolved | PromiseLike<TResolved>) | null,
      onrejected?: ((reason: unknown) => TRejected | PromiseLike<TRejected>) | null,
    ): PromiseLike<TResolved | TRejected> {
      return Promise.resolve(this.rows).then(onfulfilled, onrejected);
    }
  }

  const db = {
    query: {
      orders: {
        findMany: async ({ where }: { where: { id: { in: string[] } } }) =>
          where.id.in.map((id) => ({ id, reference: `ORD-${id}` })),
      },
    },
    selectDistinct: () => new Builder([]),
    $with: () => ({ as: () => ({ id: orders.id }) }),
    with: () => ({
      select: (selection: Record<string, unknown>) => {
        if ("rowCount" in selection) {
          trace.countQueries += 1;
          return new Builder([{ rowCount }]);
        }
        return new Builder(pages.shift() ?? []);
      },
    }),
  };

  return { db, trace };
}
// ---cut-before---
import { createQueryEngine } from "drizzle-resource";

import { relations } from "./relations";
import { schema } from "./schema";

const { db, trace } = createFakeDb([
  [
    { id: "order_1", __cursor_0: new Date("2026-01-03"), __cursor_1: "order_1" },
    { id: "order_2", __cursor_0: new Date("2026-01-02"), __cursor_1: "order_2" },
    { id: "order_3", __cursor_0: new Date("2026-01-01"), __cursor_1: "order_3" },
  ],
]);

const resource = createQueryEngine({ db, schema, relations })
  .withContext<{ orgId: string }>()
  .defineResource("orders", {
    query: {
      defaults: { pagination: { mode: "cursor" } },
      pagination: { modes: ["cursor"] },
      scope: (f, ctx) => f.is("customerId", ctx.orgId),
    },
  });

const page = await resource.query({
  context: { orgId: "acme" },
  request: {
    filters: [],
    pagination: { cursor: null, mode: "cursor", pageSize: 2 },
    search: { fields: [], value: "" },
    sorting: [{ dir: "desc", key: "createdAt" }],
  },
});

// Two rows returned, three requested — the lookahead row decides `hasNextPage`.
console.log(page.rows.length, trace.limits, trace.countQueries);
// 2 [ 3 ] 0
```

The third stub row is never returned. Cursor mode asks for `pageSize + 1`, uses the extra row to decide whether a `nextCursor` exists, and runs zero count queries because cursor requests default to `count: "none"`.

Note that the stub rows carry two `__cursor_` aliases even though the request named one sort field. The engine appended the `id` tiebreaker, and a stub row missing `__cursor_1` throws `Cursor values must be database scalar values` while encoding the next cursor.

::warning
A fake database proves wiring, not SQL. It cannot catch a wrong join, a mis-scoped `EXISTS` subquery, or a broken `count(distinct …)`. Keep a small integration suite against real Postgres for the SQL itself, and use fakes for policy and pagination logic.
::
