A data table holds four pieces of state. Each maps onto exactly one key of the request, which is why a resource endpoint needs no per-table glue.

| Table UI                   | Request key  | Notes                                    |
| -------------------------- | ------------ | ---------------------------------------- |
| Column sort headers        | `sorting`    | ordered, multi-column                    |
| Per-column filter controls | `filters`    | one condition node per active column     |
| Global search box          | `search`     | `value` plus optional `fields`           |
| Pager                      | `pagination` | `pageIndex` is **one-based**             |
| Filter sidebar counts      | `facets`     | requested per field, returned as buckets |

## Sharing the contract

Derive the client's types from the resource instead of hand-writing them. One module, imported by both sides, keeps column ids and row shapes honest:

```ts twoslash [shared/orders.contract.ts]
import type { QueryFieldPath, QueryRequestInput } from "drizzle-resource";

import type { ordersRelations, ordersResource } from "./orders.resource";
import type { relations } from "./relations";
import type { schema } from "./schema";

/** Every field path the resource exposes, derived from schema and relations. */
export type OrderFieldPath = QueryFieldPath<
  typeof schema,
  typeof relations,
  "orders",
  typeof ordersRelations
>;

/** The hydrated row shape the endpoint returns. */
export type OrderRow = Awaited<ReturnType<typeof ordersResource.query>>["rows"][number];

/** The exact payload the endpoint accepts. */
export type OrdersRequest = QueryRequestInput;
```

A column id typed as `OrderFieldPath` cannot drift from the schema — deleting a column breaks the table definition at compile time rather than at runtime.

One caveat survives the type sharing. Timestamps are `Date` on the server and strings after JSON transport:

```ts twoslash
import type { ordersResource } from "./orders.resource";

type OrderRow = Awaited<ReturnType<typeof ordersResource.query>>["rows"][number];

declare const row: OrderRow;
row.createdAt;
//  ^?
```

Either narrow the client type with a mapped `Omit`, or transform the column in `responseSchema` so both sides agree on a string. Do not let the shared type claim `Date` on a value the client received as text.

## Sorting

Table libraries keep sort state as an ordered list of `{ id, desc }`. The request wants `{ key, dir }` in the same order:

```ts twoslash [table-state.ts]
import type { QueryFieldPath, QuerySortDescriptor } from "drizzle-resource";

import type { ordersRelations } from "./orders.resource";
import type { relations } from "./relations";
import type { schema } from "./schema";

type OrderFieldPath = QueryFieldPath<
  typeof schema,
  typeof relations,
  "orders",
  typeof ordersRelations
>;
// ---cut-before---
interface ColumnSort {
  id: OrderFieldPath;
  desc: boolean;
}

export function toSorting(sorting: ColumnSort[]): QuerySortDescriptor[] {
  return sorting.map((column) => ({ key: column.id, dir: column.desc ? "desc" : "asc" }));
}
```

Send `[]` when no header is active and the resource applies its own `sort.defaults` — do not send a hardcoded fallback from the client.

Only paths without a `many` step are sortable, so a column rendering `orderLines.product.name` or `tags.name` must not be sortable in the UI. Sending one throws `Sorting field "…" is not allowed`; disable the header instead of catching the error.

## Column filters

Each active column contributes one condition node. The operator depends on the control, not on the column type:

| Control        | Operator   | Value shape                                                  |
| -------------- | ---------- | ------------------------------------------------------------ |
| Text input     | `contains` | `"laptop"` — compiles to `lower(col) LIKE lower('%laptop%')` |
| Single select  | `is`       | `"pending"` — case-insensitive on text columns               |
| Multi select   | `isAnyOf`  | `["pending", "shipped"]` — compiles to `or(eq, eq)`          |
| Numeric range  | `between`  | `{ from: 100, to: 500 }` — **an object, never a tuple**      |
| Date range     | `between`  | `{ from: "2026-01-01" }` — one-sided bounds are allowed      |
| Boolean toggle | `is`       | `true`                                                       |

Typing the filter state as a union keeps each control paired with the value shape its operator expects:

```ts twoslash [table-state.ts]
import type { QueryFilterNode } from "drizzle-resource";

export type ColumnFilter =
  | { id: "reference"; value: string }
  | { id: "status"; value: string[] }
  | { id: "isPriority"; value: boolean }
  | { id: "totalAmount"; value: { from?: number; to?: number } }
  | { id: "createdAt"; value: { from?: string; to?: string } };

export function toFilters(columnFilters: ColumnFilter[]): QueryFilterNode[] {
  return columnFilters.map((filter): QueryFilterNode => {
    switch (filter.id) {
      case "reference":
        return { type: "condition", key: filter.id, operator: "contains", value: filter.value };
      case "status":
        return { type: "condition", key: filter.id, operator: "isAnyOf", value: filter.value };
      case "isPriority":
        return { type: "condition", key: filter.id, operator: "is", value: filter.value };
      default:
        return { type: "condition", key: filter.id, operator: "between", value: filter.value };
    }
  });
}
```

Drop a column from the array when its control is cleared. An empty `isAnyOf` array compiles to a false predicate and matches nothing, which reads to the user as a broken table.

Top-level conditions are combined with `and`. Reach for a `group` node only when one control needs internal `or` logic.

## The full request

Assemble the four pieces in one place so every fetch goes through the same mapping:

```ts twoslash [table-state.ts]
import type { QueryFilterNode, QueryRequestInput, QuerySortDescriptor } from "drizzle-resource";

interface TableState {
  sorting: QuerySortDescriptor[];
  filters: QueryFilterNode[];
  globalFilter: string;
  pageIndex: number;
  pageSize: number;
}

export function toQueryRequest(state: TableState): QueryRequestInput {
  return {
    pagination: {
      mode: "offset",
      // Table indexes are usually zero-based; the request is one-based.
      pageIndex: state.pageIndex + 1,
      pageSize: state.pageSize,
      count: "exact",
    },
    sorting: state.sorting,
    filters: state.filters,
    search: { value: state.globalFilter, fields: [] },
    facets: [{ key: "status", mode: "exclude-self", limit: 20 }],
  };
}
```

Offset mode with `count: "exact"` is what a numbered pager needs — `pageInfo.rowCount` gives the total and `hasNextPage` gives the next-button state. It is the default for offset requests, so the explicit `count` is documentation rather than necessity.

Leaving `search.fields` empty hands the choice of searchable columns to the resource. The client never needs to know which columns are indexed for search.

## Facet buckets to a filter sidebar

Request a facet per sidebar section and the response carries the buckets, already ordered by count descending then value ascending, with null buckets removed:

```ts twoslash [filter-sidebar.ts]
import type { QueryFacetResult } from "drizzle-resource";

export interface SidebarSection {
  key: string;
  hasMore: boolean;
  options: Array<{ count: number; label: string; value: unknown }>;
  totalBuckets: number;
}

export function toSidebar(facets: QueryFacetResult[] = []): SidebarSection[] {
  return facets.map((facet) => ({
    key: facet.key,
    // `nextCursor` is only present when the facet request set a `limit`.
    hasMore: typeof facet.nextCursor === "string",
    options: facet.options.map((option) => ({
      count: option.count,
      label: String(option.value),
      value: option.value,
    })),
    totalBuckets: facet.total ?? facet.options.length,
  }));
}
```

`total` is the bucket count before the limit was applied, so a section showing 20 of 340 values can say so without a second request.

`mode` decides whether a section counts itself. Use `exclude-self`, the default, for a multi-select section — the other options keep their counts after the user picks one. Use `include-self` when the counts must reflect the fully filtered set.

::warning
Facet buckets come from `count(distinct id)` over the same filtered set as the page. A bucket count is the number of matching **rows**, not the number of matching related records — a `tags.name` bucket of `12` means twelve orders carry that tag.
::

Long bucket lists paginate on their own. Send `limit` plus the previous `nextCursor` to fetch the next slice, and `search` to filter buckets by text — both documented in [Facet Counts](/query-contract/facets).

## Reading the page back

`pageInfo` is a discriminated union, so narrow on `mode` before touching mode-specific fields:

```ts twoslash
import { ordersResource } from "./orders.resource";

const result = await ordersResource.query({
  context: { orgId: "acme" },
  request: {
    filters: [],
    pagination: { mode: "offset", pageIndex: 1, pageSize: 25, count: "exact" },
    search: { fields: [], value: "" },
    sorting: [{ dir: "desc", key: "createdAt" }],
  },
});
// ---cut-before---
const pager =
  result.pageInfo.mode === "offset" && result.pageInfo.count === "exact"
    ? {
        pageCount: Math.ceil(result.pageInfo.rowCount / result.pageInfo.pageSize),
        pageIndex: result.pageInfo.pageIndex - 1,
        total: result.pageInfo.rowCount,
      }
    : null;

console.log(pager);
```

`rowCount` is `null` unless the request asked for `count: "exact"`, and the union encodes that — the narrowing above is what makes `rowCount` a `number`.
