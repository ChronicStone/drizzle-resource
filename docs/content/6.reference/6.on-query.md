---
title: onQuery
description: "Hook every statement the engine runs: which stage it belongs to, which request shape asked for it, how long it took, with its SQL and no parameter values."
---

`onQuery` is called once for every statement the engine runs. Use it to log slow statements, feed a metrics library, or assert in a test how many statements a request costs.

## Usage

```ts twoslash
import { createQueryEngine } from "drizzle-resource";
import { db, relations, schema } from "./twoslash-support";
// ---cut---
const engine = createQueryEngine({
  db,
  schema,
  relations,
  onQuery: (event) => {
    if (event.ms > 200) {
      console.warn(`${event.resource} ${event.stage} ${Math.round(event.ms)} ms`, event.shape);
    }
  },
});
```

The hook runs after the statement finished, on the request's own call stack. It never changes a result: an error it throws, or a promise it rejects, is ignored, and the engine does not wait for a promise it returns. Keep it fast and push slow work (a network call, a database write) onto a queue.

## The event

| Field      | Meaning                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `resource` | The root table key of the resource.                                                                                             |
| `stage`    | What the statement is for, see below.                                                                                           |
| `shape`    | The [request shape](#request-shape) as one line, for log lines and metric labels.                                               |
| `shapeKey` | The same shape as an object: `{ resource, filters, sorting, search, facets, pagination, count }`. Each event gets its own copy. |
| `ms`       | Wall-clock milliseconds, including the round trip to the database.                                                              |
| `rows`     | Rows the statement returned. A page asks for one more row than its size when it looks ahead.                                    |
| `sql`      | The statement with `$1` placeholders. Parameter values are never included.                                                      |
| `error`    | Only when the statement failed. The engine still throws or degrades exactly as it would without the hook.                       |

| Stage     | Statement                                                                                                                                       |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `ids`     | The page: the ids of the rows, in order.                                                                                                        |
| `count`   | The count of an `exact` or `capped` page. An `estimated` count reports its plan as a `plan` statement.                                          |
| `rows`    | The rows of the page, with their relations: one statement.                                                                                      |
| `facets`  | One statement per facet or per group of facets (see [`splitAbove`](/query/facets)), and one for a facet's `missing` count.                      |
| `summary` | The [summary](/resource/summaries) aggregate.                                                                                                   |
| `plan`    | The engine's own planning: an `EXPLAIN` it runs to choose a search plan or read an estimate, and the catalog reads for indexes and table sizes. |
| `scan`    | The cursor statements of a [bulk scan](/scale/bulk-scans): `declare`, each `fetch` and `close`.                                                 |

Control statements (`begin`, `commit`, and the `set_config` that applies a [timeout](/scale/performance)) are not reported. A statement that runs out of its time budget is reported with its `error`, and the retry that follows is a statement of its own.

Statements you run yourself in a [strategy](/scale/strategies) are not seen. The `utils` methods a strategy calls report like any other statement.

## Request shape

A shape names what a request asks for and never what it asks with. Two requests with the same shape get the same string, so it is safe as a log field or a metric label:

```text
orders · filter createdAt:between,status:is · sort createdAt desc · search customer.name · facets status:exclude-self · offset · count exact
```

| Part     | Reads                                                                                                           |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| `filter` | Each condition as `key:operator`, sorted. An `or` group reads `(a:is\|b:is)`. The resource's scope is left out. |
| `sort`   | Keys with their direction. The `id` tie-breaker the engine appends is left out unless its direction differs.    |
| `search` | The searched fields, sorted. Absent when the search text is empty.                                              |
| `facets` | Each facet as `key:mode`, sorted.                                                                               |
| tail     | The pagination mode, `offset` or `cursor`, then `count` with its mode.                                          |

The page index, the page size, the cursor and every filter and search value are not part of it.

## Cost

Without an `onQuery`, a statement goes through one boolean check, allocates nothing for the hook and is awaited as before. Measured on PostgreSQL 18: 46 ns per statement through the wrapper against 45 ns for a bare `await`, noise next to a statement that takes 0.3 ms or more. With a hook that does nothing, the engine adds about 1 µs per statement to build the event.
