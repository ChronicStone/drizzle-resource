title: Types
description: All public TypeScript types exported from drizzle-resource.
---

All types are exported from the package root:

```ts twoslash
import type {
  QueryRequest,
  QueryResponse,
  // ...
} from "drizzle-resource";
```

## Request types

### `QueryRequest`

The full shape of a query request. See [Query Contract → Request Shape](/query/request-shape).

```ts twoslash
import type { QueryRequest } from "drizzle-resource";

type QueryRequestExample = QueryRequest;
```

### `QueryPagination`

```ts twoslash
import type { QueryPagination, QueryPaginationInput } from "drizzle-resource";

type NormalizedPagination = QueryPagination;
type TransportPagination = QueryPaginationInput;
```

### `QueryFacetRequest`

```ts twoslash
import type { QueryFacetRequest } from "drizzle-resource";

type QueryFacetRequestExample = QueryFacetRequest;
```

### `ResourceQueryExecutionOptions`

Trusted server-side limits for one direct resource execution. These options are not part of the transport request.

```ts twoslash
import type { ResourceQueryExecutionOptions } from "drizzle-resource";

const exportExecution = {
  maxPageSize: 5_000,
} satisfies ResourceQueryExecutionOptions;
```


### `QueryPageCount`

The count part of `pageInfo`. `count` is the mode that was used, which can differ from the one requested.

```ts twoslash
import type { QueryCountMode, QueryPageCount } from "drizzle-resource";

type RequestedCount = QueryCountMode; // "none" | "exact" | "capped" | "estimated"
type ReportedCount = QueryPageCount;
```

### `QueryFacetResult`

A union on `status`: `ok`, `skipped` (with `reason: "above-cap"`) or `timeout`. The engine always sets `status`; it is optional in the type so facets written by hand keep compiling, and an absent `status` means `ok`.

```ts twoslash
import type { QueryFacetResult } from "drizzle-resource";

type QueryFacetResultExample = QueryFacetResult;
```

### `QueryFacetsResponse`


## Engine types

### `QueryEngine<...>`

Returned by `createQueryEngine(...)`. The generic parameters are inferred from your database, schema, and relations.

### `QueryResource<...>`

The type of a defined resource, returned by `engine.defineResource(...)`. Exposes `query`, `findById`, `queryIds`, `queryRows`, and `queryFacets`. Its `$infer.query`, `$infer.findById`, and `$infer.profiles` members expose operation and profile row types without executing a query.

### `ResourceHydrationConfig<TAvailable, TProfiles>`

Defines named relation subsets and the default profiles for `query` and `findById`. Profile keys, inline `load` overrides, and returned row shapes stay inferred from the resource's relation capability graph.

### `QueryFieldPath<TSchema, TRelations, TRoot, TWith>`

The union of every dotted field path for a resource root and relation tree. Sort keys, filter keys and facet keys are checked against it.
