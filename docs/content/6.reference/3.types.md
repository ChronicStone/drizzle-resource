title: Types
description: All public TypeScript types exported from drizzle-resource.
---

All types are exported from the package root:

```ts twoslash
import type {
  QueryRequest,
  QueryResponse,
  // ...
} from "drizzle-resource";
```

## Request types

### `QueryRequest`

The full shape of a query request. See [Request shape](/query/request-shape).

```ts twoslash
import type { QueryRequest } from "drizzle-resource";

type QueryRequestExample = QueryRequest;
```

### `QueryPagination`

```ts twoslash
import type { QueryPagination, QueryPaginationInput } from "drizzle-resource";

type NormalizedPagination = QueryPagination;
type TransportPagination = QueryPaginationInput;
```

### `QueryFacetRequest`

```ts twoslash
import type { QueryFacetRequest } from "drizzle-resource";

type QueryFacetRequestExample = QueryFacetRequest;
```

### `ResourceQueryExecutionOptions`

Trusted server-side limits for one direct resource execution. These options are not part of the transport request.

```ts twoslash
import type { ResourceQueryExecutionOptions } from "drizzle-resource";

const exportExecution = {
  maxPageSize: 5_000,
} satisfies ResourceQueryExecutionOptions;
```


### `QueryPageCount`

The count part of `pageInfo`. `count` is the mode that was used, which can differ from the one requested.

```ts twoslash
import type { QueryCountMode, QueryPageCount } from "drizzle-resource";

type RequestedCount = QueryCountMode; // "none" | "exact" | "capped" | "estimated"
type ReportedCount = QueryPageCount;
```

### `QueryFacetResult`

A union on `status`: `ok`, `skipped` (with `reason: "above-cap"`) or `timeout`. The engine always sets `status`; it is optional in the type so facets written by hand keep compiling, and an absent `status` means `ok`.

```ts twoslash
import type { QueryFacetResult } from "drizzle-resource";

type QueryFacetResultExample = QueryFacetResult;
```

### `QueryFacetsResponse`

```ts twoslash

```

## Scan types

The types behind [`resource.scan`](/query/bulk-scans).

### `QueryScanRequest`

The `filters`, `sorting` and `search` of a request, all optional. A scan takes no pagination or facets.

```ts twoslash
import type { QueryScanRequest } from "drizzle-resource";

const scanRequest = {
  filters: [{ type: "condition", key: "status", operator: "is", value: "shipped" }],
} satisfies QueryScanRequest;
```

### `QueryScanBatch<TRow>`

What the iterable given to your callback yields: `rows`, and `totalRows` when the scan was asked for an exact count.

```ts twoslash
import type { QueryScanBatch } from "drizzle-resource";

type QueryScanBatchExample<TRow> = QueryScanBatch<TRow>;
```

### `QueryScanCountMode`

```ts twoslash
import type { QueryScanCountMode } from "drizzle-resource";

type ScanCount = QueryScanCountMode; // "none" | "exact"
```

## Summary types

The types behind [summaries](/query/summaries).

### `SummarySelection`

What a resource's `summary` callback returns: an object of Drizzle SQL expressions, keyed by the name each total gets.

```ts twoslash
import type { SummarySelection } from "drizzle-resource";

type SummarySelectionExample = SummarySelection;
```

### `SummaryResult<S>`

The summary a query returns, with each key typed from its expression. It is also `typeof resource.$infer.summary`.

```ts twoslash
import type { SummaryResult, SummarySelection } from "drizzle-resource";

type SummaryResultExample<S extends SummarySelection> = SummaryResult<S>;
```

## View and model types

### `ResourceView`

The shape of one entry of a resource's `views`: `{ select }`, where `select` names the fields and relations the view returns. See [Views](/resource/views).

### `ModelDefinitions`

The type of the engine's `models` option: per table, the `private` and `hidden` column names and the `virtual` fields. See [Models](/resource/models).

### `VirtualField<T>`

What the `virtual.text`, `virtual.number`, `virtual.boolean`, `virtual.timestamp` and `virtual.scalar` helpers return: the field's `kind`, whether it is `nullable`, and a `resolve` function that builds its SQL expression.

```ts twoslash
import type { VirtualField } from "drizzle-resource";

type VirtualFieldExample = VirtualField;
```

## Engine types

### `QueryEngine<...>`

Returned by `createQueryEngine(...)`. The generic parameters are inferred from your database, schema, and relations.

### `QueryResource<...>`

The type of a defined resource, returned by `engine.defineResource(...)`. Exposes `query`, `findById`, `queryIds`, `queryRows`, `queryFacets`, `querySummary`, `scan`, `explain` and `checkIndexes`; see [Resource methods](/reference/methods). Its `$infer.query`, `$infer.findById`, and `$infer.profiles` members expose operation and profile row types without executing a query.

### `ResourceHydrationConfig<TAvailable, TProfiles>`

Defines named relation subsets and the default profiles for `query` and `findById`. Profile keys, inline `load` overrides, and returned row shapes stay inferred from the resource's relation capability graph.

### `QueryFieldPath<TSchema, TRelations, TRoot, TWith>`

The union of every dotted field path for a resource root and relation tree. Sort keys, filter keys and facet keys are checked against it.
