A view lists the exact fields a response includes. Each view gets its own inferred row type, and fields outside it are never selected.

Pick an audience below: fields outside its view drop out of the response.

::view-shapes
::

## Declare views

```ts twoslash
import { count, sql, sum } from "drizzle-orm";
import { createQueryEngine, virtual } from "drizzle-resource";
import { db } from "./db";
import { schema } from "./schema";
import { relations } from "./relations";

const engine = createQueryEngine({
  db,
  schema,
  relations,
  models: {
    orders: { private: ["deletedAt"] },
    customers: {
      hidden: ["orgId"],
      virtual: (customer) => ({
        displayName: virtual.text(sql`upper(${customer.name})`),
      }),
    },
  },
}).withContext<{ orgId: string }>();

const orders = engine.defineResource("orders", {
  relations: { customer: true },
  views: {
    list: {
      select: {
        id: true,
        reference: true,
        totalAmount: true,
        customer: { select: { id: true, displayName: true } },
      },
    },
    internal: {
      select: {
        id: true,
        customer: { select: { id: true, name: true, orgId: true } },
      },
    },
  },
  query: {
    scope: (f, context) => f.is("customer.orgId", context.orgId),
    search: { allowed: ["reference", "customer.displayName"] },
  },
  summary: (order) => ({
    rows: count(),
    totalAmount: sum(order.totalAmount),
  }),
});

type ListRow = typeof orders.$infer.views.list;
//   ^?
```

`select` is exact:

- `true` on a relation returns that table's default fields, without its own relations or virtuals.
- A selected to-one relation keeps the nullability Drizzle declares. A to-many relation is an array.
- [Hidden](/resource/models) fields and virtuals are only returned when a view selects them. [Private](/resource/models) fields can't be selected.
- Internal ordering ids are removed when the view doesn't select them.

## Use a view

Pass `view` to `query`, `findById`, `queryRows` or `scan`:

```ts
const page = await orders.query({ context, request, view: "list" });
```

The view is chosen by your server, per endpoint. It is not part of the client request, and choosing a view does not authorize the caller: keep authorization in the [scope](/resource/scope).

Pass either `view` or `load` ([load profiles](/resource/relations#load-profiles)), not both. With neither, the resource's load defaults and the model rules apply.

## Validate the response

The Zod and Valibot `responseSchema` helpers accept a view and follow the same private and hidden rules. See [Validation](/validation/schemas#response-schemas).
