---
title: Pagination
description: Offset and cursor pagination, optional exact counts, stable sorting, and performance tradeoffs.
---

Pagination is a discriminated union. Offset mode supports numbered pages, while cursor mode supports stable forward traversal without paying for increasingly large SQL offsets.

## Offset pagination

```ts twoslash
import type { QueryRequest } from "drizzle-resource";

const pagination: QueryRequest["pagination"] = {
  mode: "offset",
  pageIndex: 1,
  pageSize: 25,
  count: "exact",
};
```

`pageIndex` is 1-based. The engine translates page 1 to offset 0 and page 500 with a page size of 25 to offset 12,475.

The response describes the same mode:

```ts twoslash
import type { QueryOffsetPageInfo } from "drizzle-resource";

const pageInfo: QueryOffsetPageInfo = {
  mode: "offset",
  pageIndex: 1,
  pageSize: 25,
  hasNextPage: true,
  count: "exact",
  rowCount: 12_483,
};
```

## Cursor pagination

Enable cursor mode on the resource and optionally make it the default:

```ts twoslash
// ---cut-start---
import type { ResourceQueryConfig } from "drizzle-resource";
type ExampleQueryConfig = Pick<
  ResourceQueryConfig<any, any, any, any, any, any>,
  "pagination" | "defaults" | "sort"
>;
// ---cut-end---
const query = {
  pagination: { modes: ["cursor", "offset"] },
  defaults: {
    pagination: { mode: "cursor", pageSize: 25 },
  },
  sort: {
    defaults: [{ key: "createdAt", dir: "desc" }],
  },
} satisfies ExampleQueryConfig;
```

The first request omits the cursor. Subsequent requests send the opaque `nextCursor` returned by the previous page:

```ts twoslash
import type { QueryRequestInput } from "drizzle-resource";

const firstPage: QueryRequestInput["pagination"] = {
  mode: "cursor",
  pageSize: 25,
};

const nextPage: QueryRequestInput["pagination"] = {
  mode: "cursor",
  cursor: "opaque-cursor-from-the-previous-response",
  pageSize: 25,
};
```

Cursor mode requires a visible, sortable root `id` field and automatically appends it to the effective sorting when needed. A request sorted by `createdAt desc` therefore becomes `createdAt desc, id desc`, which keeps traversal deterministic when several rows share the same timestamp.

The engine fetches `pageSize + 1` IDs. The extra ID determines whether `nextCursor` should be populated and is not included in `rows`.

```ts twoslash
import type { QueryCursorPageInfo } from "drizzle-resource";

const pageInfo: QueryCursorPageInfo = {
  mode: "cursor",
  pageSize: 25,
  nextCursor: "opaque-next-cursor",
  count: "none",
  rowCount: null,
};
```

Reset the cursor to `null` whenever sorting, filters, search, or scope inputs change. A cursor represents a position in one ordered result set.

## Exact counts are optional

Cursor pagination defaults to `count: "none"`, because computing an exact total requires scanning the complete filtered result and removes a large part of the performance benefit. Request it explicitly when the interface needs a total:

```ts twoslash
import type { QueryRequestInput } from "drizzle-resource";

const pagination: QueryRequestInput["pagination"] = {
  mode: "cursor",
  cursor: null,
  pageSize: 25,
  count: "exact",
};
```

`pageInfo.count` narrows `rowCount` safely:

```ts twoslash
import type { QueryPageInfo } from "drizzle-resource";

declare const pageInfo: QueryPageInfo;

if (pageInfo.count === "exact") {
  pageInfo.rowCount;
  //       ^?
} else {
  pageInfo.rowCount;
  //       ^?
}
```

Offset defaults to `count: "exact"`; cursor defaults to `count: "none"`. Either mode accepts the other policy, so an offset-powered “load more” endpoint can also skip the count.

## Validation and limits

`validation.maxPageSize` applies to both modes. `validation.maxCursorLength` defaults to 2,048 characters and protects both direct core calls and Zod or Valibot transport schemas.

```ts twoslash
// ---cut-start---
import type { ResourceQueryValidationConfig } from "drizzle-resource";
// ---cut-end---
const validation = {
  maxPageSize: 100,
  maxCursorLength: 1024,
} satisfies ResourceQueryValidationConfig;
```

Cursor pagination improves deep sequential traversal, but it cannot jump directly to page 500 or calculate a page count without an exact total. Keep offset mode for numbered navigation and use cursor mode for feeds, infinite scrolling, exports, and “load more” interfaces.
