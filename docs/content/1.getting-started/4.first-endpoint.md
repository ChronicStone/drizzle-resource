A resource is a server-side object. To expose it, validate the incoming body and supply the caller's context yourself.

The rule that shapes everything on this page: **the request body carries what to query, the session carries who is asking.** Those two must never mix.

## Derive the request schema

`requestSchema` builds a validator from the resource itself — its allowed filter paths, sortable fields, search fields, facet keys, pagination modes, defaults, and limits:

```ts twoslash
import { requestSchema } from "drizzle-resource/zod";

import { ordersResource } from "./orders.resource";
// ---cut-before---
export const ordersRequestSchema = requestSchema(ordersResource);
```

There is no second contract to maintain. Narrowing the resource narrows the endpoint automatically.

::note
Use `drizzle-resource/valibot` for the same API with Valibot. Both are covered in [Validation](/integration/validation).
::

## The handler

Parse the body, reject on failure, then pass the parsed request through with a context you built from the session:

```ts twoslash
import { requestSchema } from "drizzle-resource/zod";

import { ordersResource } from "./orders.resource";

const ordersRequestSchema = requestSchema(ordersResource);
declare function getSession(req: Request): { orgId: string; userId: string };
// ---cut-before---
export async function handleOrdersQuery(req: Request): Promise<Response> {
  const session = getSession(req);
  const parsed = ordersRequestSchema.safeParse(await req.json());

  if (!parsed.success) {
    return Response.json({ issues: parsed.error.issues }, { status: 400 });
  }

  const result = await ordersResource.query({
    context: { orgId: session.orgId, userId: session.userId },
    request: parsed.data,
  });

  return Response.json(result);
}
```

`parsed.data` is accepted directly — no cast. The schema's output type is the resource's request type.

## What the client sends

Everything is optional except the values the client actually wants to change. Omitted keys fall back to the resource defaults:

```json
{
  "pagination": { "mode": "offset", "pageIndex": 1, "pageSize": 25 },
  "sorting": [{ "key": "createdAt", "dir": "desc" }],
  "search": { "value": "laptop", "fields": [] },
  "filters": [
    { "type": "condition", "key": "status", "operator": "isAnyOf", "value": ["pending"] }
  ],
  "facets": [{ "key": "status", "mode": "exclude-self", "limit": 10 }]
}
```

A body of `{}` is valid and returns the first page with the resource's default sort.

## What the client gets back

```json
{
  "rows": [{ "id": "…", "reference": "ORD-1042", "customer": { "name": "Acme" } }],
  "pageInfo": {
    "mode": "offset",
    "pageIndex": 1,
    "pageSize": 25,
    "hasNextPage": true,
    "count": "exact",
    "rowCount": 143
  },
  "facets": [{ "key": "status", "options": [{ "value": "pending", "count": 12 }], "total": 3 }]
}
```

## Why context stays out of the body

`orgId` comes from the session, never from the payload. The schema deliberately omits `context` from the transport shape, so a client cannot send one:

```ts twoslash
// @errors: 2353 2379
import { requestSchema } from "drizzle-resource/zod";

import { ordersResource } from "./orders.resource";

const ordersRequestSchema = requestSchema(ordersResource);
// ---cut-before---
ordersRequestSchema.parse({
  pagination: { mode: "offset", pageIndex: 1, pageSize: 25 },
  context: { orgId: "someone-elses-org" },
});
```

The scope filter built from your context merges into every query and cannot be widened by client input — that guarantee is the subject of [Scope Rules](/resource-setup/scope).
